# Java Backend — правила нашого навчання

> Цей файл — постійне джерело домовленостей між учнем і ChatGPT. Він описує **як ми навчаємося**, а не зберігає код занять чи щоденний журнал.
>
> Створено: 2026-10-26. Правила можна доповнювати й коригувати за домовленістю.

## 1. Мета й напрям

- Мета — здобути практичні навички Java Backend і підготуватися до першої роботи Java Backend Developer (віддалений формат бажаний).
- Рухаємося послідовно: міцна Java Core → ООП і колекції → Generics, Exceptions, Maven, тестування → SQL → Spring Boot, REST API, робота з базою даних → проєкти та підготовка до працевлаштування.
- Не перескакуємо до складних технологій без розуміння основ; план можна адаптувати до темпу та прогресу.

## 2. Ролі під час занять

- **Учень самостійно пише код**, запускає його й робить коміти у GitHub.
- **ChatGPT — наставник**: пояснює матеріал, добирає практичні завдання, відповідає на питання, дає підказки, перевіряє надісланий код і пропонує поліпшення.
- Не писати готове розв'язання навчального завдання наперед. Повний приклад/розв'язання надавати, коли учень прямо попросить або коли ми спільно вирішимо розібрати його.
- Якщо виникла складність — спочатку невелика підказка; за потреби наступна, конкретніша. Важлива самостійна спроба.

## 3. Формат пояснень і практики

- Пояснення та фідбек — **українською**.
- Назви змінних, методів, класів, а також текстові літерали у прикладах Java — **англійською**, щоб не доводилося перемикати розкладку.
- Подаємо матеріал невеликими порціями: пояснення → завдання → рішення учня → перевірка → розбір помилок → наступний крок.
- Під час рев'ю перевіряємо не лише правильність результату, але й зрозумілість, логіку, крайні випадки та якість коду; відрізняємо критичні помилки від необов'язкових поліпшень.
- Теорію пов'язуємо з реальними задачами backend, поступово підвищуючи складність.

## 4. Навчальний ритм і прогрес

- Орієнтир навантаження: **близько 18 годин на тиждень** (раніше узгоджений план: 2 години × 5 днів та 4 години × 2 дні). Графік гнучкий щодо роботи, поїздок і відпочинку.
- Якщо немає комп'ютера, можна проводити коротке заняття з теорією телефоном; практичне написання коду — коли є можливість.
- Використовуємо мотиваційну систему: рівні, XP, пройдені етапи та streak. **XP нараховується за реально виконані й перевірені завдання, а не за сам факт розмови.**
- Рівні прив'язуємо до навчальних етапів/навичок, а не випадкових чисел.
- **Загальна кількість навчальних днів і streak — різні показники.** Станом на 2026-10-25 підтверджено 16 навчальних днів загалом; актуальний streak не слід вгадувати.

## 5. GitHub і збереження домовленостей

- Учень сам керує навчальним кодом і комітами у репозиторії `java-backend-learning`. ChatGPT **не комітить код із занять** і не змінює його без окремого прохання.
- Цей файл `LEARNING_RULES.md` зберігає **тільки правила й довготривалі домовленості**, не історію кожного заняття.
- Коли ми домовляємося про нове правило або змінюємо старе, ChatGPT **під час цієї розмови**, за наявності доступу GitHub, оновлює цей файл: коригує відповідний пункт або додає новий; не створює дублікати.
- У новому чаті за потреби спочатку перечитуємо цей файл, щоб відновити формат роботи після втрати контексту.
- Зміни не виконуються у фоновому режимі чи автоматично між чатами; якщо GitHub недоступний, ChatGPT прямо повідомляє про це.
- **Наприкінці кожного завершеного уроку** ChatGPT перевіряє, чи з'явилися нові домовленості або чи змінилися чинні правила навчання та плани пет-проєктів. Якщо так — **оновлює цей самий файл** на GitHub: редагує старі положення або додає нові без дублікатів, зберігаючи незмінені розділи. Якщо змін немає — файл не чіпає.
- Після перевірки наприкінці уроку ChatGPT коротко повідомляє, чи було оновлено правила. Якщо доступу до GitHub немає — прямо повідомляє, що оновлення не вдалося. Це виконується **під час нашої розмови**, не у фоновому режимі.

## 6. Пет-проєкти: ідеї та пріоритети

Це **узгоджений перелік ідей і кандидатів для портфоліо**, а не зобов'язання реалізувати все одночасно. Конкретний порядок і складність уточнюємо після відповідних тем Java Backend.

### Основні кандидати для backend-портфоліо

1. **Smart Wallet / Finance Tracker** — застосунок обліку доходів і витрат, категорій, бюджетів та статистики. Орієнтовний стек на відповідному етапі: Java, Spring Boot, REST API, PostgreSQL, тести, Docker; за бажанням простий frontend.
2. **Restaurant Management System** — backend для ресторану: меню, замовлення, працівники, склад, ролі та авторизація. Планований напрям: Spring Boot + база даних + REST API. Не плутати з навчальною OOP-мініверсією.
3. **JARVIS — персональний AI/voice-асистент** — власний довгостроковий проєкт для голосових команд, керування комп'ютером і автоматизації. **Не стартувати завчасно**: спочатку впевнене володіння Java Core і backend. Код пише учень; ChatGPT лише наставляє, пояснює архітектуру, допомагає з планом і перевіряє написане.

### Раніше розглянуті тренувальні / портфоліо-ідеї

- **ATM System** — симуляція банкомата.
- **Task Manager** — задачі та статуси на кшталт Trello.
- **Internet Shop** — backend інтернет-магазину.
- **McDonald's Manager System** — система для роботи ресторану (концептуально перетинається з Restaurant Management System).
- **Booking System** — система бронювань.

Не вважаємо ці п'ять ідей обов'язковими окремими проєктами. Перед початком нового проєкту погоджуємо його мету, мінімальний функціонал та технології. **Навчальний код і коміти залишається відповідальністю учня.**
